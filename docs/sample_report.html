ATTACK ARP spoofing by de:ad:be:ef:00:66 high severity · 95% confidence

What happened: Device de:ad:be:ef:00:66 keeps announcing that it owns 192.168.1.10, 192.168.1.1 (the gateway), addresses that belong to other devices. It sent 28 ARP replies nobody asked for. Computers that believe it send their traffic to the impostor instead of the real device, so it can read or alter that traffic (man-in-the-middle). It poisons both sides of a conversation at once, the typical man-in-the-middle setup.

Likely cause: An attacker on the local network running an ARP-poisoning tool.

Suggested fix: Locate the device with MAC de:ad:be:ef:00:66 (switch port table) and disconnect it. Enable Dynamic ARP Inspection / port security if your switch supports it, and use static ARP entries for the gateway on critical machines.
